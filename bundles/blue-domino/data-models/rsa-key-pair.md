# RSA256 Key Pair

## Summary

An RSA256 public-private key pair used for signing JWT tokens in the token generation system. The key pair is generated and managed by the Key Vault Manager service, stored in Azure Key Vault, and utilized by the Token Data Service for JWT token signing. Each key pair follows a 90-day lifecycle with a structured rotation schedule to ensure continuous availability of valid signing keys.

## Details

### Generation

The RSA256 key pair is generated by the Key Vault Manager as a public-private key pair. Both the public and private keys are exported in PEM format and stored as strings in Azure Key Vault. Generation occurs on a scheduled basis according to the rotation schedule, with the Key Vault Manager running as a cron job every 24 hours to check key age and expiration.

### Format and Storage

- **Format**: PEM files (public and private keys stored as strings)
- **Storage Location**: Azure Key Vault
- **Storage Type**: Secrets within Azure Key Vault

### Lifecycle and Rotation Schedule

Each RSA256 key pair follows a standardized 90-day lifecycle:

- **Day 1**: Key pair is introduced into Azure Key Vault
- **Day 3 to Day 83**: Key becomes the primary signing key, active for 80 days
- **Day 80**: A new key pair is introduced, remaining inactive for 3 days
- **Day 84 to Day 90**: Original key remains in Azure Key Vault in an inactive state
- **Day 91**: Original key is deleted after reaching the end of its 90-day lifecycle

### Metadata and Tracking

Each key pair stored in Azure Key Vault is associated with:
- Creation date (used to calculate key age)
- Set expiration date of 90 days

The Key Vault Manager uses these dates to determine when to introduce new key pairs and delete expired ones. The Token Data Service assigns primary or secondary status to keys based on their age and position in the rotation schedule.

### Usage

The Token Data Service retrieves RSA256 key pairs from Azure Key Vault on application startup and performs the following operations:

- Assigns primary and secondary roles to keys based on their age
- Generates JWKS (JSON Web Key Set) from public keys
- Caches both JWKS and private keys in memory
- Uses the primary private key to sign JWT token payloads for each token request
- Refreshes the in-memory cache every 24 hours with updated keys from Azure Key Vault
