# Key Vault Manager (KVM)

## Summary

Key Vault Manager (KVM) is an independent Golang service implemented as a scheduled cron job responsible for managing the lifecycle of RSA key pairs in Azure Key Vault. Running every 24 hours, KVM generates new keys, rotates existing keys according to a defined schedule, and deletes expired keys—ensuring Azure Key Vault always contains valid keys without directly impacting the Token Data Service.

## Details

### Purpose and Scope

KVM operates independently from the Token Data Service (TDS) and manages the complete lifecycle of RSA key pairs used for JWT token signing. Unlike TDS, which assigns primary and secondary roles to keys based on age, KVM focuses solely on generating new keys, tracking their age and expiration, and removing expired keys according to the established rotation schedule.

### Key Generation and Rotation

KVM generates RSA256 public-private key pairs and stores both the public and private PEM files as strings in Azure Key Vault as secrets. Each new key pair is created according to a defined rotation schedule:

- **Day 1**: KVM introduces a new key pair into Azure Key Vault
- **Day 3–83**: The new key becomes the primary signing key, active for 80 days
- **Day 80**: KVM introduces another new key pair, which remains inactive for 3 days before becoming primary
- **Day 84–90**: The original key remains in Azure Key Vault in an inactive state
- **Day 91**: KVM deletes the original key after reaching the end of its 90-day lifecycle

### Key Expiration and Age Tracking

Each key created by KVM is associated with:

- A creation date (used to calculate key age)
- A fixed expiration date of 90 days

KVM monitors key age and expiration to determine when to introduce new keys and delete expired ones. This tracking allows KVM to maintain predictable key availability without requiring manual intervention.

### Operation as a Scheduled Task

KVM is configured to run as a cron job, executing every 24 hours. During each execution, it:

1. Checks the age and expiration of existing keys in Azure Key Vault
2. Generates new key pairs as needed according to the rotation schedule
3. Removes keys that have reached the end of their 90-day lifecycle

By managing key lifecycle independently, KVM ensures that Azure Key Vault contains up-to-date keys available for TDS to fetch and cache, enhancing both security and performance.
